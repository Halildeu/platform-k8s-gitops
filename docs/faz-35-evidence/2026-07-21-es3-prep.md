## ES-306 — Security verification pack

### Test kanıtları (test cell'de agent-doable — 2026-07-21)

| Test | Sonuç | Değerlendirme |
|---|---|---|
| Concurrent rate-limit (30 parallel POST, `limit-rps: 5`) | 5×201 + 1×503 + 24×504 | ⚠️ **BLOCKER**: `429` dönmedi — backend overload'a yenildi. Rate-limit + backpressure hardening gerek |
| Reflected XSS `<script>alert(1)</script>` in subject/description | 201 kabul, persist | ⚠️ Input sanitize edilmedi. React auto-escape defense-in-depth ise OK ama backend validation eksik |
| SSRF `http://169.254.169.254/latest/meta-data/` gövde içinde | 201 kabul, persist | ⚠️ Server-side fetch yok → doğrudan SSRF değil, payload persist |
| Invalid enum `HACK_ATTEMPT` | 400 (silent) | ✓ Enum validation çalışıyor |
| Oversized description (17000 char > 16000) | `VALIDATION_FAILED` | ✓ Size validation çalışıyor |
| SQL injection payload | 201 kabul | ✓ JPA/Hibernate prepared statement — DB'ye zarar yok |
| Empty Authorization header | 401 | ✓ ingress-nginx basic-auth strict |
| IDOR: staff bearer → public API | 401 | ✓ Provider-boundary reject |
| IDOR: farklı access-secret ile receipt | `RESOURCE_UNAVAILABLE` | ✓ Obfuscation ("wrong" vs "not found" leak yok) |

### ES-3 için gerekli iş

**BLOCKER'lar:**
1. **Rate-limit hardening** — 504 pattern kapatılacak. ingress-nginx `limit-rps` + `limit-connections` + `limit-burst` doğru render? Backend'de reactive backpressure? Circuit breaker (Resilience4j) yeterli mi?
2. **Input sanitization** — subject/description/reporter reply body defense-in-depth (backend'de HTML-escape + sanitizer whitelist, frontend'de `dangerouslySetInnerHTML` kullanılmadığından emin olma)

**Ek:**
- SBOM scan (Trivy) `ethics-service` + `etik-speak-manager` + `etik-speak-public` images (CI'da mevcut mu?)
- CSRF token verify — mailbox POST'ları session cookie zaten var, ancak `SameSite=Strict` ile cross-site protection ✓ observed
- File upload malware scan (attachment ES-1'de skip — ES-3'te ES-104 tam olmalı)

**Owner action gerek**: Backend PR (Codex tercih, agent alternatifi mevcut) + frontend audit (`dangerouslySetInnerHTML` grep).

## 4. Findings — Codex REVISE Absorb Verifications

### 4.1 Mock receiver Slack-format error (expected, drill-only)

Alertmanager log:
```
time=2026-05-24T16:17:33.879Z level=ERROR source=dispatch.go:603
msg="Notify for alerts failed"
err="direct-fallback/slack[0]: notify retry canceled due to unrecoverable error after 1 attempts:
channel \"#alerts-d43-drill\": received an error response from Slack:
{\"received\":true,\"path\":\"/slack-mock\",\"correlation\":\"\"}"
```

**Açıklama (Codex REVISE absorb #3 doğrulandı)**: webhook-receiver nginx response body `{"received":true,...}` Slack API contract'e uymadığı için Alertmanager Slack receiver "unrecoverable error" log'lar. **HTTP POST DELIVERY** yine de **başarılı (200)** — webhook-receiver nginx log capture etti. Gerçek Slack workspace webhook'da bu hata `"ok"` text response ile çözülür (board #853). Mock drill için **POST receipt evidence yeterli**.

### 4.2 Resolve email + slack-mock POST asimetrisi

Mailpit: 2 firing email (T+0 dispatch + group_interval=5m repeat).
Slack mock POST: 1 (sadece T+0).

**Açıklama**: Alertmanager pipeline first dispatch'te Slack leg fail edince ("unrecoverable" log) retry yok; sonraki repeat'lerde **email leg tek başına devam**, Slack POST yok. Bu mock-specific davranış — gerçek Slack webhook'da retry sequence farklı. Drill amacı **first dispatch dual receipt kanıtı**, o sağlandı.

### 4.3 Schema compatibility (Operator v0.90.1)

İlk helm upgrade attempt fail oldu:
```
err="provision alertmanager configuration: failed to initialize from secret:
yaml: unmarshal errors: line 30: field auth_username_file not found in type config.plain"
```

**Fix**: email_configs `auth_username_file`/`auth_password_file` removed; Mailpit no-auth mode (require_tls=false). Operator v0.90.1 stricter schema'da auth_*_file mevcut değil. Prod SMTP relay (Office 365) için `auth_username`/`auth_password` inline (Vault'tan template'le inject) gerekir — RB-notification-outage-fallback.md §6.5.8 referans, prod activation'da revisit.

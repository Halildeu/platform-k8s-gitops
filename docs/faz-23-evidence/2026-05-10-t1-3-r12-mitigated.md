## Service Implementation

`ProviderConfigService.switchActive(Long fromConfigId, Long toConfigId, String reason)`:

```java
@Transactional(isolation = Isolation.SERIALIZABLE)
public void switchActive(Long fromConfigId, Long toConfigId, String reason) {
    // Load + validate (active source, inactive target, same tuple)
    // Insert immutable ProviderConfigHistory snapshot
    // Deactivate source + Activate target (atomic)
    // TransactionSynchronization.afterCommit { invalidateCache() }
}
```

**Key design decisions**:
- `@Transactional(SERIALIZABLE)`: PG concurrent serialization
- `TransactionSynchronization.afterCommit`: cache invalidation post-commit (concurrent reader doesn't observe stale)
- PG partial unique index `idx_provider_active(org_id, provider_key, environment) WHERE active=TRUE`: race-loser hits constraint violation
- History row immutable (PG rule `ON UPDATE/DELETE DO INSTEAD NOTHING` + JPA `@Immutable`)

### Test #2: concurrent_switch_race

2 threads aynı source'tan farklı target'lara switch dener; PG partial unique index serializes:
- Winner: commits successfully + history insert + state flipped
- Loser: throws one of `IllegalStateException`, `DataIntegrityViolationException`, `CannotAcquireLockException`, `PessimisticLockingFailureException`, or `TransactionSystemException`

End state: exactly one active provider; history has 1 row.

### Test #3: cache_invalidate

Cache TTL 1s configured; `switchActive()` `TransactionSynchronization.afterCommit` hook clears cache post-commit. `findPrimary()` immediately returns new active.

### Test #4: rollback_on_fail

`provider_key` mismatch → `IllegalStateException` → `@Transactional` rollback. History row count unchanged; both configs preserve original active state.

## 1. Codex 6 default → implementation

### Default 1: Branch protection solo pattern

**Codex recommend:** `Require PR + Block direct pushes + Admin bypass OK + 0 reviewer + status checks after workflow`.

**Impl:** Faz 19.2 PR-A merge sonrası branch protection enable edilecek:
- `main` branch required PR before merge
- Admin bypass allowed (solo developer deadlock önleme)
- Status check `ci-mvn-check` required

### Default 2: CI MVP tek workflow

**Codex recommend:** Root-level single workflow, batch scope `-pl auth-service,user-service,variant-service -am`, opt-in full reactor via dispatch.

**Impl:** `.github/workflows/ci-mvn-check.yml`:
- Triggers: push main + pull_request main + workflow_dispatch
- Default mode: batch scope compile + verify
- Opt-in: `workflow_dispatch inputs.mode=full-reactor`
- Temurin JDK 21 + Maven cache

### Default 3: Image naming korundu

**Codex recommend:** `platform-backend` CI aynı GHCR isimlerine (`platform-ssot-*`) push eder (en az hareketli parça, D30 digest pin).

**Impl:** Image pattern 19.8'de netleşir; Faz 19.2 scope'ta sadece compile check, image push yok.

### Default 4: Zanzibar batch sıralama

**Codex recommend:** 19.2'de auth/user/variant common-auth compile-time bağımlılığı korunur; 19.3'te common-auth + openfga-runtime taşınır (relocation POM köprüsü gerekirse eklenecek).

**Impl:** Batch 1 PR-A kapsamı sadece CI + docs; kod değişikliği yok. common-auth 19.3'te ayrı PR.

### Default 5: Root pom.xml reactor

**Codex recommend:** Root'ta reactor build CI'da kanıtlanacak.

**Impl:** `parent-backend/pom.xml` root'ta 9 modül (common-auth + discovery-server + api-gateway + auth-service + permission-service + user-service + variant-service + core-data-service + report-service). `./mvnw -q -DskipTests -pl <scope> -am verify` batch doğrulanır.

### Default 6: 2-PR yaklaşımı

**Codex recommend:** PR-A (CI + hijyen) + PR-B (kod refactor eğer gerekli).

**Impl:** PR-A yayınlandı (platform-backend PR #1). PR-B gereği 19.3+'ta değerlendirilecek (initial push yeterli şu an).
